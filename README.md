# Панель кабинетов (Ozon + Wildberries)

Личный дашборд сразу по двум кабинетам — Ozon и Wildberries: заказы и выручка
за последние 7 дней, чистая прибыль (с учётом себестоимости), процент
выкупа, расходы площадки (комиссия/логистика/хранение), реклама и ДРР,
товары с риском нехватки остатков, и короткий список конкретных задач на
сегодня по каждому кабинету. Обновляется сам, каждое утро, без вашего
участия. При критичных задачах — дополнительно присылает уведомление в
Telegram.

Кабинеты полностью независимы друг от друга: если, например, у Wildberries
истёк ключ или его вообще ещё не подключили — Ozon-часть страницы всё равно
обновится как обычно. Ни один кабинет не может сломать другой.

Как это работает: раз в сутки GitHub Actions запускает
`scripts/build_dashboard.py`, скрипт заходит в API Ozon и Wildberries,
пересчитывает цифры и пересобирает `index.html`, который показывает GitHub
Pages.

## Установка (один раз)

### 1. Создайте репозиторий

На github.com → New repository → назовите, например, `ozon-panel` → Create.
Загрузите туда все файлы из этой папки (кнопка **Add file → Upload files**,
можно просто перетащить всё мышкой) и нажмите **Commit changes**.

### 2. Добавьте ключи Ozon как Secrets

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.

Добавьте два секрета:
- `OZON_CLIENT_ID` — Client-Id из личного кабинета продавца Ozon (Настройки → Seller API)
- `OZON_API_KEY` — соответствующий Api-Key

Эти значения нигде не показываются в интерфейсе после сохранения — это безопасное место.

Wildberries можно подключить сразу же (см. раздел ниже) или позже — без него
страница просто покажет по Wildberries мягкую карточку «ещё не подключено»,
ничего не сломается.

### 3. Включите GitHub Pages

**Settings → Pages** → в разделе Source выберите **Deploy from a branch**,
ветка **main**, папка **/ (root)** → Save.

Через минуту-две сайт появится по адресу:
`https://yulyakudryavtseva1-ctrl.github.io/ozon-panel1/`
(вместо имени подставьте то, что получилось у вас).

Важно: бесплатный GitHub Pages работает только с публичными репозиториями —
если ваш репозиторий приватный, либо сделайте его публичным (Settings →
Danger Zone → Change visibility), либо оформите платный GitHub Pro. Публичный
репозиторий значит, что код и сама страница видны всем, у кого есть ссылка
(но нигде не публикуется и не индексируется сама по себе).

### 4. Запустите первое обновление вручную

**Actions** (вкладка вверху репозитория) → слева выберите workflow
**«Обновление панели кабинетов»** → справа кнопка **Run workflow** → Run workflow.

Через 1-2 минуты обновите страницу сайта — на ней должны появиться ваши
реальные цифры по Ozon (и по Wildberries, если уже подключили). Дальше это
будет происходить само каждое утро в 9:00 МСК.

## Подключение Wildberries

### Получить ключ

1. В личном кабинете Wildberries: **Профиль → Доступ к API**
   (`https://seller.wildberries.ru/api-integrations`) → создать новый токен.
2. При создании токена отметьте категорию **«Статистика»** — этого
   достаточно для всех цифр на странице (заказы, остатки, возвраты, расходы).

### Добавить как Secret

Так же, как ключи Ozon: **Settings → Secrets and variables → Actions →
New repository secret**.

- `WB_API_KEY` — токен, который вы создали

**Честно предупреждаю:** в отличие от Ozon-части этого проекта (уже проверена
вживую и работает), интеграция с Wildberries написана по открытой
документации и статьям, но не проверена реальным вызовом — у меня нет
доступа к вашему кабинету WB, чтобы протестировать её заранее. Почти
наверняка после первого настоящего запуска что-то по мелочи потребует
поправки (например, имя поля в ответе API) — это нормально, так же было и с
рекламным кабинетом Ozon в своё время. Если после добавления ключа по
Wildberries показывается «не удалось получить данные» — откройте
**Actions → последний запуск → шаг «Забрать данные Ozon и Wildberries,
пересобрать страницу»**, скопируйте текст ошибки и пришлите мне, поправим
по факту.

У Wildberries Statistics API строгий лимит — примерно 1 запрос в минуту на
метод, поэтому скрипт устроен так, чтобы делать всего 3 запроса за весь
прогон. Реклама Wildberries (WB Advert API) пока не подключена — это
отдельный, более сложный API, можно добавить отдельным шагом позже.

## Себестоимость и чистая прибыль

Чтобы дашборд считал не просто выручку, а настоящую чистую прибыль, ему
нужно знать себестоимость каждого товара (закупка, упаковка и т.п.). Это
единственное, что вводится не автоматически, а вручную — через простой файл
`data/costs.json` в самом репозитории.

Откройте файл `data/costs.json`, отредактируйте его (например, скачайте,
поправьте в блокноте, залейте обратно через **Add file → Upload files**,
подтвердив замену) и заполните по образцу:

```json
{
  "ozon": {
    "мой-offer-id-товара": 450,
    "другой-offer-id": 1200
  },
  "wb": {
    "12345678": 300
  }
}
```

- В `"ozon"` ключ — это `offer_id` (артикул) товара в Ozon.
- В `"wb"` ключ — это `nmId` (артикул) товара в Wildberries.
- Значение — сколько стоит одна единица товара в рублях.

Товар, которого нет в файле, просто не учитывается в расчёте чистой прибыли —
остальная страница при этом не ломается. Пока файл пустой (как сразу после
установки), карточка «Чистая прибыль» по соответствующему кабинету покажет
«нужна себестоимость» вместо цифры. Если часть проданных товаров есть в
файле, а часть — нет, страница честно покажет «частично» и сколько единиц
осталось без цены.

Себестоимость нигде не запрашивается автоматически ни у Ozon, ни у
Wildberries — обновлять `costs.json` при изменении цен закупки нужно
вручную, тем же способом.

## Уведомления в Telegram (опционально, но рекомендуется)

Если на сайте появляется что-то критичное (остаток товара вот-вот кончится,
резкий провал заказов, высокий ДРР, низкий процент выкупа — по любому из
кабинетов) — бот сам напишет вам в Telegram, не нужно каждый день открывать
сайт, чтобы это заметить. Если секреты ниже не настроены — сайт всё равно
работает как обычно, просто без уведомлений.

### Создать бота (2 минуты, в самом Telegram)

1. Откройте в Telegram чат **@BotFather** → отправьте `/newbot`.
2. Придумайте имя (любое) и username бота (должен заканчиваться на `bot`,
   например `yulya_ozon_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — это и есть `TELEGRAM_BOT_TOKEN`. Никому его не показывайте, кроме поля
   Secret на GitHub (см. ниже).
4. Напишите вашему новому боту любое сообщение (например «привет») — иначе
   он не сможет писать вам первым.
5. Откройте в браузере (замените TOKEN на ваш токен):
   `https://api.telegram.org/botTOKEN/getUpdates`
   В ответе найдите `"chat":{"id":123456789,...}` — это число и есть
   `TELEGRAM_CHAT_ID`.

**Важный совет из личного опыта:** копируйте токен и chat_id через
Telegram-кнопку копирования (тап/клик по самому тексту), а не выделением
мышкой вручную — при ручном выделении легко перепутать похожие символы
(например строчную «л» и заглавную «I» в разных шрифтах). Также если в
чате с BotFather включён автоперевод («Перевод (русский)» баннер сверху) —
лучше временно отключить его для этого чата: перевод иногда искажает
моноширинный текст токена при копировании.

### Добавить как Secrets

Так же, как с ключами Ozon: **Settings → Secrets and variables → Actions →
New repository secret**.

- `TELEGRAM_BOT_TOKEN` — токен от BotFather
- `TELEGRAM_CHAT_ID` — число из getUpdates

Уведомление придёт только если есть критичные/требующие внимания задачи —
бот не будет писать вам каждый день просто чтобы отчитаться.

## Реклама и ДРР (Ozon, опционально)

Это отдельный от Seller API кабинет — Ozon Performance API, со своими
ключами. Без него блок «Реклама и ДРР» по Ozon остаётся заглушкой и ничего
не ломает. (Реклама Wildberries пока не подключена вообще — см. раздел про
Wildberries выше.)

### Получить ключи

1. В личном кабинете Ozon: **Настройки → API-ключи → Performance API →
   Добавить ключ**.
2. Скопируйте оба значения: **Client ID** и **Client Secret**. Это не те же
   самые ключи, что `OZON_CLIENT_ID`/`OZON_API_KEY` из первого шага —
   отдельная пара, специально для рекламного кабинета.

### Добавить как Secrets

Так же, как остальные: **Settings → Secrets and variables → Actions →
New repository secret**.

- `OZON_PERFORMANCE_CLIENT_ID`
- `OZON_PERFORMANCE_CLIENT_SECRET`

Эта интеграция уже проверена вживую и работает (домен `api-performance.ozon.ru`).

## Еженедельный ИИ-разбор

Отдельно от ежедневного обновления цифр, раз в неделю запускается разбор от
Claude: не просто цифры, а что они значат и что с этим делать, по обоим
кабинетам. Результат сохраняется в проект Claude — там же, где хранятся
остальные заметки по этим кабинетам, — и приходит вам как уведомление.

## Если что-то пошло не так при первом запуске

Откройте **Actions → «Обновление панели кабинетов» → последний запуск**,
разверните шаг «Забрать данные Ozon и Wildberries, пересобрать страницу» —
там будет текст ошибки. Чаще всего это означает, что у конкретного метода
API изменилось имя поля или путь. Для Ozon сверьтесь с
https://docs.ozon.ru/api/seller/ (открывайте только этот официальный
домен), для Wildberries — с https://dev.wildberries.ru/. Пришлите мне текст
ошибки, поправим.

Сайт устроен так, что одна неудачная попытка по одному кабинету не сломает
ни другой кабинет, ни уже работающую страницу — при ошибке используются
данные последнего успешного запроса по этому конкретному кабинету, а второй
кабинет в это время обновляется как обычно.

Если API вернул `429 Too Many Requests` — это не баг, а лимит частоты
запросов, обычно после нескольких ручных перезапусков подряд (у Wildberries
лимит особенно строгий — около 1 запроса в минуту на метод). Подождите
15–30 минут и попробуйте снова.

## Посмотреть, как это выглядит, без реального ключа

Локально (или попросите меня показать): `python scripts/build_dashboard.py --demo`
соберёт `index.html` на синтетических примерах по обоим кабинетам, ничего не
запрашивая у Ozon или Wildberries.

## Подключить свой домен позже

**Settings → Pages → Custom domain** — впишите купленный домен и настройте
у регистратора домена DNS-запись по инструкции, которую покажет GitHub.
